# Notes for coding agents

Read README.md first. This is a pnpm monorepo, written in TypeScript throughout.

## Commands
- `pnpm test`: vitest for the engine and the server room logic. Run it after any change to the rules or the room.
- `pnpm typecheck`: tsc in every package.
- `pnpm build`: builds `apps/web/dist`, which the server serves.
- `pnpm --filter @hearts/server exec wrangler deploy --dry-run`: checks the Worker bundle without deploying it.

## Where things go
- Game rules belong in `packages/engine` only. It must stay pure: no DOM, no timers, no I/O. The browser and the server both call `apply`, `viewFor` and `nextBotAction`.
- Messages sent over the wire belong in `packages/protocol`. Change the valibot schema and the TS types together.
- Room behaviour (seats, ready, bots, reconnect) belongs in `apps/server/src/room-core.ts`. It is platform-neutral. `worker.ts` (Cloudflare) and `node.ts` (Node) are thin adapters around it.
- UI components and screens belong in `packages/ui`. Every component and screen has a Storybook story. Add or update the story whenever you change one. Screens take data and callbacks through props, with sample data as defaults.
- `apps/web` wires the screens to the engine (solo play) or to a WebSocket (online play) through the `GameController` type in `src/controller.ts`.

## Design system rules
- Use the semantic tokens (`bg-surface`, `text-fg`, `text-muted`, `text-accent-ink`, …). Never hard-code colours. There are 4 themes (`felt` is the default; `glass`, `playful`, `xp`), each with light and dark.
- `packages/ui/src/vendor/xp-scoped.css` is generated by `packages/ui/scripts/scope-xp.mjs` from XP.css. Never edit it by hand.
- XP theme: no transitions; animations are linear and use XP timings (see `src/tokens/xp.css`).
- Touch: targets are at least 44 pt on coarse pointers, the UI has no text selection, and nothing requires a drag (the hand also has a "Card list").
- Text sizes use rem so they follow the system text size. Spacing uses px.
